Buttons

A button runs an action; a link drawn as a button goes somewhere. One class, btn, then a tone, a size or an icon when the button needs one.

Examples

The plain btn is neutral. btn-primary marks the one main action of a screen; the other tones say what an action does.

Outline, subtle, text and link

Quieter forms of the same tones for secondary actions, rows and toolbars. btn-text has no fill until hovered; btn-link reads as a link and keeps a button's size.

Sizes

A size is a word: btn-xs 24 px, btn-sm 28 px, the default 32 px, btn-lg 40 px — the heights of every control of the same size.

Icons

An icon sits beside the words, or alone in a square btn-icon whose name is its aria-label. btn-close draws the close glyph by itself.

Groups and toolbars

btn-group joins buttons into one control — here a choice of view, each button pressed or not. btn-toolbar lays groups and buttons out in a wrapping row.

Toggle and busy

A toggle carries aria-pressed. While its action runs, REDZ.ui.busy(button, promise) shows a spinner in the button and marks it aria-disabled: it keeps the focus and ignores clicks until the promise settles.

States

A state is the attribute accessibility needs anyway, on the button itself: no active or disabled classes. aria-expanded is set by the browser on a button that opens a menu or a dialog.

Keyboard and accessibility

  • <button type="button"> for an action, <a href> for a place; btn draws both the same. Enter and Space press a button, Enter follows a link.
  • A button with only an icon takes its name from aria-label; the icon is aria-hidden="true".
  • disabled takes a button out of the tab order and hides why. aria-disabled="true" keeps it focusable — so a tooltip can say why — and the library swallows its clicks.
  • A button that opens a menu or a dialog uses the browser's command: commandfor + command, never data-bs-toggle.
  • The focus ring is 2 px of --redz-focus, 3:1 against the page in both themes.
