Sign-in

The browser's side of a sign-in: passkeys by the JSON forms a server gives and takes, the way out of an app's own browser to the real one, and the proof of work a form solves before it is sent. The page fetches and posts everything; the library holds no network and no words of its own.

Two files of the release

The sign-in package is linked apart, on the screens that sign in, after the library's script, which gives it the busy state and the toasts. It has no styles: its controls are the page's own buttons and links.

<script type="module" src="redz-ui/js/redz-ui-signin.min.js"></script>

The proof file, js/redz-ui-proof.min.js, stands alone: a classic script that needs no other file of the library and writes no markup, so a page that loads nothing else of the library - a public form of a site with its own theme - runs it too. It is never linked as a module: the sign-in package starts it as a worker, and a page without the package starts it itself.

What this browser can do

REDZ.ui.passkey.probe() answers in one call what the screen needs to choose its way: whether passkeys work here, and in which app's browser the page is. Below is its answer for the browser reading this page.

Passkeys

The server gives the options as WebAuthn Level 3 JSON, PublicKeyCredentialCreationOptionsJSON or PublicKeyCredentialRequestOptionsJSON, binary members in base64url, and takes back what credential.toJSON() gives. The library reads the options by the browser's own calls where it has them and by itself where it does not, leaves out the members that are null, which some browsers refuse, and builds the answer member by member where a password manager's extension hands back a credential whose toJSON breaks. Fetch the options before the press, so the ceremony is the first thing the press does.

const options = await fetch('/sign-in/options').then((answer) => answer.json());
button.addEventListener('click', async () => {
	const result = await REDZ.ui.passkey.get(options, {busy: button});
	if (result.ok) {
		await fetch('/sign-in', {method: 'POST', body: JSON.stringify(result.response)});
	} else if (result.code === 'in_app') {
		// Offer the password, and the way out to the real browser.
	}
});
// The field's own suggestions, on an input with autocomplete="username webauthn":
REDZ.ui.passkey.autofill(() => fetch('/sign-in/options').then((answer) => answer.json())).then(send);
CallWhat it does
create(options, {busy, signal})Creates a passkey. busy is the pressed control, busy while the ceremony runs; signal ends it.
get(options, {busy, signal})Signs in by a passkey the person picks.
autofill(options, {signal})Offers the passkeys in the field's suggestions. One promise for the page: it settles when a passkey is picked there, or aborted when an explicit call succeeds, the signal ends it or a new one comes. While an explicit call runs it stands aside, and it comes back when that one fails. Its options may be a call that gives fresh ones each time it comes back, for a challenge that does not live long.
upgrade(options)Creates a passkey quietly after a password sign-in, where the browser can: nothing shows unless it works, and every failure is silent.
signal.unknown, signal.accepted, signal.userTell the passkey manager, by the Signal API, of a passkey the server does not know, of every passkey it still accepts, of the person's current names. They answer true when told, false where the browser cannot, and never wait longer than a second.

Every call answers {ok: true, response} or {ok: false, code, name}, never a browser's own message; name is the browser's error name, for the page's own records.

CodeWhat it means
unsupportedThe browser has no passkeys, or not the one asked: offer another way.
in_appThe page is in an app's own browser, which refuses passkeys; app names it. A call refused faster than a person can act, in under 300 ms, is such a browser the library could not name: app is unknown.
cancelledThe person closed the prompt, or its time ran out: the two cannot be told apart.
existsCreating: this device already holds a passkey the server listed.
blockedThe domain or a policy does not allow it.
abortedThe page ended the call: nothing to show.
failedAnything else.

The way out of an app's browser

A link opened in a messenger opens in the app's own browser, which refuses passkeys and keeps its cookies apart from the real browser. data-open-browser on a link or a button, hidden, shows it there once it holds an address: it asks the page by redz:handoff for a ticket - an address that carries everything the real browser needs, as the cookies stay behind - asks again in the ticket's last minute while the page shows and when it shows again, and keeps its own href when the page does not answer. Its press copies the address and leaves by the app's way; where the app has none, or the page is still there a moment later, the page's text handoff.copied says the address was copied. Keep the ticket in the query: an Android intent drops what follows the #.

Open in browser

Here the first button's call is refused at once, as an app's browser refuses it: the result is in_app and the way out shows.

<a class="btn" data-open-browser hidden>Open in browser</a>
document.addEventListener('redz:handoff', (event) => {

Apps that open a link in the real browser's own tab - a Custom Tab on Android - are the real browser, and stay unnamed.

Proof of work

A form that may be sent without signing in solves a task first: a price in time that a person never notices and a flood of sends pays in full. The task is {alg: 'pbkdf2-sha256', id, cost, max, prefix, kmac, label}: its key for a counter is PBKDF2-SHA256 of the label, salted by the id's 16 bytes and the counter, cost times; the counter sought is the one whose key starts with the prefix and signs the id into the kmac. REDZ.ui.solve runs it in the proof file as a worker from the address the page gives - a string, or the page's own TrustedScriptURL under Trusted Types - and in the page where no worker can start; it answers the counter, or -1 for a task it does not know, an end by the signal or a failure.

const {token, task} = await fetch('/form/task').then((answer) => answer.json());
const found = await REDZ.ui.solve(task, {worker: '/redz-ui/js/redz-ui-proof.min.js', busy: submit});
