File upload

Photos, documents, a price list: chosen, dropped or pasted, each file checked at once and sent on its own, with its own progress and its own error.

Examples

upload holds the file input, an upload-zone button that opens it and takes files dropped on it, a <template> of one file's row and an upload-list. A paste while the focus is in the upload takes the clipboard's files. Each file is checked against the input's accept and the upload's data-max-size in bytes; a refusal shows in the file's row, the page's text file.type or file.size. A file dropped beside the zone does not open in the window.

    One file

    An input without multiple holds one file: a new one chosen, dropped or pasted takes the place of the one before - its row, its sending, its place in the input - and of several dropped at once only the first is taken.

      Thumbnails

      upload-thumbs on the upload draws its files as 5rem squares: an img data-file-preview in the row's template shows the image itself, cut to fill, its remove button on the corner; a refused file keeps a whole row for its words. data-max-files takes that many and refuses the rest with the page's text file.count. A page that prepares each image first - resized, turned upright - answers redz:files with a promise of the new file, which takes the old one's place in the input.

        upload.addEventListener('redz:files', (event) => {
  event.preventDefault();
  event.detail.respondWith(createImageBitmap(event.detail.file, {imageOrientation: 'from-image'}).then(resize));
});

        Sent by the page

        Each file fires redz:files on the upload with the file, its row, progress(fraction) for the row's bar and a signal its remove button aborts. A page that sends cancels it and answers with a promise: resolved, the row is done; resolved with the id the server gave the file - a string or a number - the row is a stored one from then on, as the server would write it, data-file-stored its id, and its Remove asks the page in redz:remove; rejected, the page's words show in the row's data-file-error. One file's error leaves the others. Left alone, the file joins the input's files and goes with the form. The example above answers in a second and a half.

        document.addEventListener('redz:files', (event) => {
	event.preventDefault();
	const {file, progress, signal} = event.detail;
	event.detail.respondWith(new Promise((sent, failed) => {
		const request = new XMLHttpRequest();
		request.open('POST', '/files');
		request.upload.onprogress = (step) => progress(step.loaded / step.total);
		request.onload = () => (request.status === 200 ? sent(request.responseText) : failed(request.responseText));
		request.onerror = () => failed('The file did not arrive');
		signal.addEventListener('abort', () => request.abort());
		request.send(file);
	}));
});

        Files the server holds

        The server writes a row for each file it holds, as the template's, with data-file-stored - its id - and the name of its remove button. Remove asks the page in redz:remove with detail.id and detail.row: a page that cancels it and answers with a promise keeps the row busy until it settles - gone when it resolves, its words said in its data-file-error when it rejects. Left alone, the row goes, and a hidden field of its own with it, so the form sends the ids still kept. After each change the upload fires redz:change with detail.count, the files it holds, stored and new, detail.pending, those still sending, and detail.failed, those refused; data-max-files counts the stored ones too. While a file sends, the file field is invalid with the page's text file.pending, so its form waits. A file the page sends becomes such a row when its redz:files promise resolves with the id the server gave it. Below, the contract is in use by an invoice, and a paper added is sent and kept under the next id.

        Pasted anywhere, cleared, settled

        A file is pasted into an upload while the focus is in it. With data-paste="page" the upload takes files pasted anywhere on the page, or, with an element's id, anywhere in that element - a ticket's card. A paste into a text field that brings words stays words, though a word processor puts a picture of them beside: only a paste of files alone goes to the upload. Of several such uploads, the one in the open modal dialog takes the files, else the one that shows. REDZ.ui.upload.clear(upload) takes away the files not yet stored - their sending aborted - and keeps the stored ones, with one redz:change and the focus where it was; a reset of the form does the same. REDZ.ui.upload.settled(upload) answers a promise of {count, pending, failed} once nothing in it is sending: a Send waits on it.

        send.addEventListener('click', async () => {
	const {failed} = await REDZ.ui.upload.settled(upload);
	if (failed === 0) {
		form.requestSubmit();
	}
});

        Keyboard and accessibility

        • The zone is one real button: Enter or Space opens the browser's picker; the input itself stays out of the Tab order, and its words - which follow the browser's language, not the page's - never show.
        • A refused or failed file says why in its row, at once; a removed file's focus goes to the next file's remove button, else to the zone.
        • Each remove button is named after its file, from the page's text remove.
